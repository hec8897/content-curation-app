# 콘텐츠 수집기 + AI 요약 계획

**목표:** 사용자가 등록한 RSS·YouTube 소스에서 실제 콘텐츠를 모으고, 주제 관련성 판단과 한국어 요약을 붙여 앱에 보여준다. 앱에 남은 목업 콘텐츠와 가짜 로딩을 전부 걷어낸다.

## 전체 흐름

```
[주제 상세 ↻ 버튼 → POST /topics/{id}/collect]
        │
        ▼
  수집기 ── 소스 주소 → 피드 주소 판별(사이트·YouTube 채널 페이지도 RSS 링크 탐색)
        │   → 피드 읽기 → items 저장(중복은 DB가 막음)
        ▼
  요약기 ── 요약 없는 아이템 → OpenAI 한 번 호출로 { 관련 있음?, 한국어 요약 }
        │   → 실패 3회까지 자동 재시도, 이후는 앱의 "다시 시도"로
        ▼
  GET /bootstrap ── 주제별 최신 아이템(관련 없음 판정은 제외) + 요약 상태
        │
        ▼
  Flutter 앱 ── 홈·주제·히스토리·아티클 상세가 실제 데이터로 그려짐
```

## 범위

| 포함 | 제외 (다음 단계) |
|---|---|
| 피드 주소 판별, RSS/Atom·YouTube 수집, 중복 방지 | 실제 발송(스케줄·채널) — ROADMAP 5단계 |
| 주제 상세의 수동 수집 버튼 | 자동 주기 수집 (2026-09-28 범위에서 제외) |
| | Alembic — 아이템은 다시 수집 가능해서 아직 `down -v`로 충분 |
| 관련성 판단 + 요약, 실패 재시도 | 썸네일 실제 이미지 |
| 앱: 목업·slug 접합점·가짜 로딩(900ms / 1100ms / `a3`) 제거 | 무한 스크롤, 주제 삭제 |

## 결정 사항

- **YouTube API 키 없이 간다.** 채널 페이지가 RSS 링크를 노출하므로 RSS와 같은 경로로 처리한다.
- **요약 모델은 `gpt-5.6-luna`.** 모델 ID·API 키는 `.env`로 둔다. 키가 없으면 요약만 건너뛰고 수집은 정상 동작한다.
- **관련성 판단과 요약을 한 호출로.** 키워드 문자열 매칭은 만들지 않는다.
- **요약은 수집 시점에 한 번.** 앱이 열 때 만들지 않으니 요약 대기 시간이 없다.
- **발송 전까지 다이제스트 = 최근 24시간 수집분.** 히스토리는 수집 날짜로 묶는다.
- **자동 루프는 이번에 하지 않는다(2026-09-28).** 수집은 주제 상세의 버튼으로만. 요약은 수집 요청 안에서 끝낸다(2026-10-05) — 판단 전 아이템을 숨기므로 응답 뒤에 돌리면 수집 직후 화면이 빈다.

## 단계

### A. 수집기 (백엔드)
1. **스키마** — `items` 테이블, 소스의 실제 피드 주소 칸 추가. 이제 필요 없는 `topics.slug` 제거.
2. **수집** — 피드 판별 → 읽기 → 저장. 소스 하나가 실패해도 나머지는 계속 수집한다. 수동 수집 라우트.
3. ~~주기 실행~~ — 제외. 대신 주제 상세 헤더에 ↻ 수집 버튼.
4. **API 노출** — `/bootstrap`의 주제마다 아이템과 요약 상태(대기·완료·실패)를 싣는다.

**완료 기준:** 가입 → 수집 한 번 → 시드 소스들에 아이템이 쌓이고, 재수집해도 늘지 않는다. YouTube 소스에 피드 주소가 채워진다.

### B. AI 요약 (백엔드)
5. **요약기** — 수집 직후 대기 아이템을 요약. 개별 재요약 라우트("다시 시도"용).

**완료 기준:** 영어 원문도 한국어 2~3문장으로 요약되고 무관한 글은 걸러진다. 키가 없거나 모델이 틀려도 수집은 멈추지 않는다.

### C. 앱 연결 (Flutter)
6. **목업 제거** — 서버 아이템으로 교체, 다이제스트·히스토리를 실제 날짜로, 홈 가짜 로딩 제거.
7. **요약 상태** — 아티클 상세가 서버의 요약 상태대로 로딩·완료·실패 카드를 보여주고, 재시도가 실제로 동작한다.

**완료 기준:** 새 계정으로 온보딩부터 아티클 상세까지 목업 없이 동작한다.

### D. 문서
8. CLAUDE.md·ROADMAP·README에 파이프라인과 새 환경변수 반영.

## 주의할 입력

1. **사이트 주소만 입력한 소스**(예: anthropic.com/engineering) — 피드를 못 찾으면 그 소스만 건너뛴다.
2. **YouTube `@핸들` 주소** — 채널 피드로 바뀌어야 한다.
3. **guid·날짜가 없는 피드 항목** — 링크와 수집 시각으로 대신하고, 재수집해도 중복되지 않아야 한다.
4. **API 키 미설정·요약 오류** — 수집은 정상, 3회 실패 후 앱에 실패 카드.
5. **본문이 매우 긴 글** — 요약 입력 길이에 상한을 둬 비용을 막는다.

## 운영 메모

- 스키마를 바꾸므로 `docker compose down -v`가 필요하다. Postgres는 모든 worktree가 공유하니 다른 worktree 데이터도 함께 지워진다.
- 요약 품질은 실제 결과 10건쯤을 읽고 판단한다. 부족하면 프롬프트나 `SUMMARY_MODEL`만 바꾼다.
- 수집량이 커지면 병렬 수집, 요약 Batch API(50% 할인), 같은 피드 공유 수집 순으로 확장한다.
